# Design

## Context

First engine change after `bootstrap-workspace`. It turns bytes into facts: probe (ADR-0010), metadata and
formats (ADR-0017), photo classification (ADR-0015) and thumbnails (ADR-0016). Everything here is pure functions
over byte slices or readers, except the thumbnail store, which is SQLite and therefore an I/O crate (ADR-0003).
Read-only access to sources is a hard rule (ADR-0004).

## Goals / Non-Goals

**Goals:**
- One probe per file that never reads more than 256 KB, and a single full read for candidates (ADR-0010).
- Total, panic-free functions on hostile input (fuzzed headers in tests).
- Explainable classification with reasons and settings-driven thresholds.
- Thumbnails fast enough for the 150 files/s analysis budget (ADR-0026).

**Non-Goals:**
- Hashing (`content-hashing`), pipeline threading (`scanning`), catalog persistence of results (`catalog`).
- Video frame decoding beyond an optional external poster-frame tool (ADR-0017).

## Decisions

- **Crates and modules.**
  - `ps-model`: `MediaFormat`, `MediaKind { Still, Video }`, `Dimensions`, `Orientation`, `ProbeRecord`,
    `Metadata`, `CaptureDate { value, provenance, undated }`, `PhotoClass`, `ClassReason`, `ClassifierSettings`.
  - `ps-media::probe` - magic sniffing (JPEG, PNG, GIF, WebP, TIFF, BMP, ICO, SVG text sniff, HEIF/AVIF `ftyp`
    brands, QuickTime/MP4 `ftyp`/`moov`, RAW by TIFF-based maker signatures and CR3 `ftyp crx`), header dimensions
    via `imagesize`, EXIF block location, embedded preview range. Input is `&[u8]` (<= 256 KB) plus file size,
    so the caller (scanner) controls I/O. A `CountingReader` test helper asserts the 256 KB bound.
  - `ps-media::metadata` - `nom-exif` for EXIF and QuickTime/MP4 (ADR-0017); `rawler` for RAW metadata and
    preview extraction; capture-date resolution order as specified; JPEG quality from DQT tables by matching
    against scaled IJG tables (least-squares over the 64 luminance coefficients).
  - `ps-media::classify` - pure `classify(&ProbeRecord, &Path, &ClassifierSettings) -> (PhotoClass, Vec<ClassReason>)`
    implementing ADR-0015 rules in a fixed order: cache path -> camera EXIF -> video rules -> graphic -> size -> likely_photo.
    Cache-folder patterns are a const table plus a settings extension list.
  - `ps-media::decode` - `jpeg-decoder` DCT scaling for the analysis decode, `zune-jpeg` for full decodes,
    `image` for PNG/TIFF/WebP/GIF/BMP, `libheif-rs` behind feature `heic` (ADR-0017). `fast_image_resize` for
    384/1024/2048 px resampling (Lanczos3). Orientation applied once, on the decoded buffer.
  - `ps-media::thumb` - JPEG encode at q82, dominant colour = mean of the 8x8 downsample in Oklab, converted to sRGB.
  - `ps-media::poster` - spawns the configured `ffmpeg` (`-ss 1 -frames:v 1 -vf scale=384:-1`) with a 10 s timeout;
    tests use a fake executable script that writes a fixture JPEG.
  - `ps-catalog::thumbs` - `thumbs.db` (separate SQLite file, WAL) with table `thumb(content_id BLOB PRIMARY KEY,
    w, h, dominant_rgb, jpeg BLOB, kind)`; `kind` distinguishes image, poster frame and placeholder. The 2048 px
    preview LRU is a directory of `<content-id-hex>.jpg` files with an index table `preview(content_id, bytes,
    last_used)`; eviction runs after each insert. The store is keyed by content identity, so this change
    accepts the identity as an opaque 32-byte key (computed in `content-hashing`).
- **Analysis decode size.** ADR-0010 says "smallest size >= 512 px"; we interpret this as the long edge (the
  32x32 perceptual input and 384 px thumbnail never need more). See Risks.
- **Decoder availability.** `ps-media::capabilities()` returns `{ heic: bool, poster_frames: Option<PathBuf> }`
  for `doctor` (ADR-0017).
- **Fixtures.** Small hand-made fixtures (JPEG with orientations 1-8, DNG with preview, MOV/MP4, palette PNG,
  ICO, corrupt files) are generated by `ps-fixtures::media` at test time from code, so no binary blobs are
  committed except a tiny HEIC sample (licence-clean, generated once with libheif and checked in, < 50 KB).

## Risks / Trade-offs

- [ADR-0010 ambiguity "smallest size >= 512 px"] -> long-edge interpretation recorded here; if perceptual hash
  quality on the corpus suffers for panoramas, switch to the short edge (no ADR change needed, it is an
  implementation detail of the decode).
- [Quality estimation on non-IJG encoders (phones)] -> estimate is a tie-breaker only (ADR-0014 rank 4).
- [Component budgets] -> the 100 ms single-core decode budget is derived from ADR-0026's 150 files/s; it is
  added to `perf-budgets.toml` as a derived entry. If maintainers treat derived entries as new budgets, an
  ADR amending ADR-0026 is needed.
- [External ffmpeg hangs] -> hard timeout and kill.

## Verification

- `cargo test -p ps-media -p ps-model -p ps-catalog thumbs` (all `scenario_media_probe_*`,
  `scenario_media_metadata_*`, `scenario_photo_classification_*`, `scenario_thumbnails_*` tests).
- `cargo test -p ps-media --no-default-features` (HEIC-off scenarios).
- `cargo bench -p ps-media --bench analyze` then `cargo xtask bench --check`.
- `cargo xtask layering` (ps-media stays core), `cargo xtask ci`.
- `openspec validate media-analysis --strict`.
