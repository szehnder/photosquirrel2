# Proposal

## Why

PhotoSquirrel is published on GitHub and should install like any desktop app on macOS, Windows and Linux, for a
user who has never installed Rust. Every release must be reproducible from a tag, carry both the app and the CLI,
be verifiable by checksum, and come with a README that shows what the app looks like.

## What Changes

- `cargo xtask package`: `dist`-profile builds, cargo-packager formats per OS (DMG; NSIS setup; AppImage + .deb),
  plus a plain archive (.tar.gz / .zip), renamed `PhotoSquirrel-<version>-<os>-<arch>.<ext>`, a `.sha256` per file,
  and a smoke test of the packaged CLI (ADR-0030).
- Linux packages built in an Ubuntu 22.04 container (glibc 2.35 floor); macOS universal (arm64 + x86_64) build.
- Tag `v<version>` workflow publishing a GitHub Release with every artifact and templated release notes;
  HEIC fallback noted when libheif is unavailable on a platform.
- README with feature overview, safety guarantees, install instructions, first-launch notes for unsigned
  builds, and screenshots generated by `cargo xtask screenshot --all-surfaces`.
- Release notes template cleaned of template leftovers (product-specific requirements: LM Studio optional,
  keyring, ffmpeg optional).

## Capabilities

### New Capabilities
- `release-packaging`: building, checking and publishing installers and documentation for every platform.

### Modified Capabilities
- None.

## Impact

- ADRs: 0017, 0026, 0029, 0030, 0031, 0032.
- Files/crates: `xtask` (`package`, `screenshot`), `crates/photosquirrel/Cargo.toml` (`[package.metadata.packager]`),
  `.github/workflows/release.yml`, `packaging/` (Dockerfile, desktop file, release notes), `README.md`, `docs/screenshots/`.

## Out of scope

- Code signing and notarization (ADR-0030 revisit); auto-update (ADR-0029); package-manager submissions
  (Homebrew, winget, Flathub); ARM Linux and ARM Windows builds.
